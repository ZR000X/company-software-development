# Principles (reader path)

This file is the **canonical ordered index** for everything under [`principles/`](principles/): read the essays in the sequence below unless you are jumping to a single topic. The essays themselves live in `principles/` as versioned, linkable notes.

If you are **authoring** or extending a principle note (frontmatter, numbered sections, references), follow the handbook in [`principles/README.md`](principles/README.md). Principle essays explain *why* we think a certain way; runnable procedures live under [`processes/`](processes/)—see [`processes/README.md`](processes/README.md).

## Read in this order

The list below is **pedagogical**: each step sets up vocabulary and stakes for the next. YAML `created` dates on individual files may differ; the order here is the recommended first pass.

1. **[Written principles and written debate](principles/01-written-principles.md)** — Alignment scales when arguments are written, inspected, and versioned before and beside live debate; the repository is an instance of that discipline.

2. **[Business as process—and process as data](principles/02-business-as-process-and-process-as-data.md)** — A business as agents changing state; processes as operations with impact versus cost; why governance and explicit data discipline track maturity.

3. **[Process versus improvisation: know the terrain](principles/03-process-vs-improv.md)** — When to encode workflow versus when improvisation fits; terrain and dominant failure modes before you standardize.

4. **[Competency lines and project delivery](principles/04-competency-vs-project-teams.md)** — The competency line owns craft, quality, and sustainable capacity; delivery owns commitments and the customer-facing value pipeline—without collapsing the two.

5. **[Agentic architecture as repository and workflows](principles/05-agentic-architecture-as-repo-and-workflows.md)** — Shared repository plus explicit workflows as the minimum architecture for coordinated human and software agents; suggested repo layers and durable run records.

6. **[Repository information architecture and the agent governance stack](principles/06-repository-ia-and-agent-governance-stack.md)** — Organizational versus team information architecture; orchestration stack (humans, agents, models, tokens); recorded, applied, and authoritative knowledge; constitution, policies, identities, and workflows as a written stack; human bootstrap and governance authority. Assumes item 5 and extends it with explicit governance layers for what agents load and who remains accountable.

7. **[Operational regime, execution, and records of work](principles/07-operational-regime-and-records-of-work.md)** — Operational regime as team orchestration; agent-centric pull versus workflow-centric triggers; workstreams, cycles, and meetings as forums; pull requests and reviewable change; logical single system of record; records of work with reason and policy or constitution references as first-class fields. Builds on item 6.

8. **[Economics, action lineage, and context isolation](principles/08-economics-action-lineage-and-context-isolation.md)** — Token economics and accounting; projects versus initiatives; action lineage from applied work to obligations and economic scope; branching and parallel directory-and-branch trees for context isolation; synthesis and combined takeaways. Builds on items 6 and 7.

Together, these notes connect written alignment, process thinking, org design, and agentic execution into one coherent path from *why we write things down* to *how work is traced, costed, audited, and bounded in context at scale*.
