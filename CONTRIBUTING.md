# Contributing

Welcome. This project documents and designs business processes in the open and aims to collaborate with others who want to co-design a company. We're glad you're here.

## How to contribute

- **Share ideas** – Open an issue to suggest a topic, process, or direction.
- **Edit or add content** – Propose changes via pull requests. Fix typos, expand notes, or add new process docs.
- **Discuss** – Use issues to ask questions and discuss how we work.

Content is plain text (Markdown). Some of it is written in [Obsidian](https://obsidian.md/); you can use any editor. AI-assisted drafts are welcome—if you used an AI tool to help write something, that's fine.

## Where to put new content

- Process and design notes go in the `docs/` folder.
- Keep new docs in Markdown (`.md`). Use a clear filename that reflects the topic.

## Pull requests and issues

- **Issues** – For ideas, questions, or reporting problems.
- **Pull requests** – For direct edits. Describe what you changed and why. We'll review and merge when it fits the project.

## Commit messages

- Use the **imperative mood** in the subject line (e.g. "Add process doc for X", not "Added process doc for X").
- Keep the **subject line** short (about 50 characters or less) and descriptive.
- Optionally add a **body** after a blank line to explain what and why, especially for larger changes.
- Reference issues or PRs in the body when relevant (e.g. "Closes #12").

**Gitmojis** – You may prefix the subject with a [gitmoji](https://gitmoji.dev/) to signal the type of change. Examples useful in this repo:

| Emoji | Code     | Use for                    |
|-------|----------|----------------------------|
| 📝    | `:memo:` | Documentation / new docs   |
| ✨    | `:sparkles:` | New feature or process |
| 🐛    | `:bug:`  | Fix typo or correction     |
| ♻️    | `:recycle:` | Refactor or restructure |
| 📌    | `:pin:`  | Pin / clarify dependencies |
| 🎨    | `:art:`  | Formatting, structure only |

Example: `📝 Add onboarding process doc` or `:memo: Add onboarding process doc`.

Please read our [Code of Conduct](CODE_OF_CONDUCT.md). By participating, you agree to uphold it.

Thanks for contributing.
